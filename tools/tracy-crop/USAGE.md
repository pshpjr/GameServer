# Tracy 시간 구간 자르기

용량 절약을 위해 Tracy 기록에서 지정한 시간 구간과 겹치는 CPU 이벤트를 추출해 별도의 `.tracy` 파일로 저장합니다. 입력 파일을 수정하진 않습니다.

**지정한 시작·종료 시간에 정확히 맞춰 자르는 것은 보장되지 않습니다. 경계에 걸친 이벤트는 온전히 포함되므로 결과에 요청 구간보다 앞뒤 시간이 포함될 수 있습니다.** 프레임 간격, plot 이웃값, 메모리 할당 수명, lock 상태 이력도 결과 범위를 늘릴 수 있습니다.

## 사용

`GameServer/tools/tracy-crop` 폴더에서 PowerShell을 열고 실행합니다. 실행 파일과 `zstd.dll`을 같은 폴더에 둡니다.

```powershell
.\tracy-crop.exe `
  'D:\path\server.tracy' `
  'D:\path\server_crop.tracy' `
  '3:40' '5:03'
```

인수 순서는 **입력 파일, 출력 파일, 시작 시간, 종료 시간**입니다. 시간은 Tracy 타임라인의 0초 기준이며 `120.5`, `2:00.5`, `00:02:00.5` 형식을 지원합니다. 소수점은 초 필드에만 쓸 수 있습니다. 종료 시간은 시작 시간보다 커야 합니다.

```powershell
.\tracy-crop.exe 'INPUT.tracy' 'OUTPUT.tracy' 'START' 'END'
.\tracy-crop.exe --help
```

## 처리 규칙과 제한

- CPU zone을 요청 구간과 겹치는 경우 유지합니다. 부모 zone도 유지되므로 부모의 self time은 원본과 달라질 수 있습니다.
- VALUE 이벤트와 CPU 사용량 plot은 요청 구간 안의 점과 보간·계단 그래프 문맥을 위한 앞뒤 한 점을 유지합니다.
- 프레임, 메모리 할당, lock 이벤트 등은 연결된 이력을 보존하기 위해 이벤트 전체를 포함할 수 있어 결과 범위가 늘어날 수 있습니다.
- 메시지, 샘플, 컨텍스트 스위치 등 시점 기반 데이터는 요청 구간 안의 항목을 유지합니다.
- 원본 시간축은 유지됩니다. 출력 파일이 이미 있거나 입력·출력 폴더가 없으면 덮어쓰지 않고 오류를 표시합니다.
- GPU zone이 포함된 캡처는 지원하지 않으며 명시적으로 거부합니다.

전체 기록을 메모리에 읽으므로 큰 파일은 충분한 메모리가 필요합니다. 출력은 먼저 `.partial` 임시 파일에 기록하고 쓰기가 끝나면 최종 파일명으로 옮깁니다. 강제 종료로 `.partial` 파일이 남으면 확인 후 직접 지우거나 다른 출력 이름을 사용하세요.

## 소스에서 빌드

빌드에는 Visual Studio C++ 도구, Python, 프로젝트의 vcpkg Tracy 0.14.1 소스 및 zstd 설치가 필요합니다. 저장소 루트(`GameServer` 소스 폴더)에서 실행합니다.

```powershell
.\GameServer\tools\tracy-crop\build.ps1
```

실행 파일과 `zstd.dll`은 `GameServer/tools/tracy-crop/`에 배치되고, 중간 빌드 파일은 `GameServer/out/build/tracy-crop/`에 생성됩니다. 빌드 스크립트는 Tracy 소스를 직접 수정하지 않고 별도 생성 파일에 필요한 메서드를 추가합니다. 라이브 캡처 기능과 병렬 정렬 라이브러리는 비활성화하고 순차 정렬 라이브러리를 사용합니다. Tracy 소스의 라이선스는 해당 저장소에 그대로 적용됩니다.
