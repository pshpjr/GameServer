# scratch 사용 규칙

## 용도

`scratch/`는 실제 서비스 코드에 포함하지 않을 각종 디버깅용 임시 코드, 버그 재현 코드, 성능 테스트, 구현 테스트 및 실험 자료를 보관하는 공간이다. 스크립트뿐 아니라 실행에 사용한 입력값과 설정, 실행 결과, 로그, 분석 기록도 함께 보관한다.

해당 자료들을 보관하는 이유는 사용자가 포트폴리오를 작성할 때 빠르게 회고하기 위함이다. 

## 폴더 구조

- `scratch/` 바로 아래에는 작업별 폴더만 만든다. 단, 공통 지침인 `AGENTS.md`와 두 템플릿 `BUG_TEMPLATE.md`, `TEST_TEMPLATE.md`는 예외로 이 위치에 둔다.
- 작업 폴더 이름은 `<이름>_<YYYY-MM-DD>` 형식으로 작성한다. 날짜는 작업 시작일이며, 이름은 작업 주제를 알아볼 수 있게 작성한다. 예: `echo-throughput_2026-09-15`.
- 각 작업 폴더의 `README.md`에는 무엇에 관한 작업인지, 목적과 배경, 관련 코드 또는 이슈, 버전별 변경 요약과 기록 링크를 작성한다.
- 스크립트가 수정되어 이전 로그와 호환이 불가능한 경우 작업 폴더 내부에 `001/`, `002/`, `003/`처럼 숫자로만 된 버전 폴더를 순서대로 만든다.

```text
scratch/
├── AGENTS.md
├── BUG_TEMPLATE.md
├── TEST_TEMPLATE.md
└── echo-throughput_2026-09-15/
    ├── README.md
    ├── 001/
    │   ├── TEST.md
    │   ├── run.ps1
    │   ├── inputs/
    │   ├── logs/
    │   └── results/
    └── 002/
        ├── TEST.md
        ├── run.ps1
        ├── inputs/
        ├── logs/
        └── results/
```

## 템플릿 사용

- 버그 조사 및 해결 기록은 [BUG_TEMPLATE.md](BUG_TEMPLATE.md)를 해당 버전 폴더의 `BUG.md`로 복사하여 작성한다.
- 성능 및 구현 테스트를 포함한 테스트 기록은 [TEST_TEMPLATE.md](TEST_TEMPLATE.md)를 해당 버전 폴더의 `TEST.md`로 복사하여 작성한다.
- 버그 조사와 검증 테스트를 함께 수행하면 하나의 문서로 합쳐서 작성한다. 
- 템플릿의 항목은 유지한다. 해당하지 않는 항목은 `해당 없음`을, 확인하지 못한 내용은 `미확인` 또는 `추가 확인 필요`로 표시한다. 가설과 확인된 사실을 구분하며, 수행하지 않은 테스트나 확인하지 않은 결과를 완료한 것으로 기록하지 않는다.
- 공통 템플릿에는 개별 작업의 내용을 작성하지 않는다.

## 스크립트 및 자료 버전 관리

- 첫 실행은 `001/`에서 시작한다. 스크립트, 구현, 입력값 또는 설정을 변경하여 비교하거나 다시 검증할 때는 다음 번호의 폴더를 만든다.
- 기존 버전의 스크립트와 결과물을 덮어쓰지 않는다. 새 버전에는 재현에 필요한 코드, 입력 데이터, 설정을 함께 보관하고 이전 버전과의 차이를 기록한다.
- 각 버전에서 사용한 임시 코드와 스크립트, 생성된 빌드 산출물, 로그, 측정값, 출력 파일, 스크린샷, 분석 자료는 모두 해당 버전 폴더 안에 저장한다. 필요하면 그 안에 `build/`, `inputs/`, `logs/`, `results/` 등의 하위 폴더를 만든다.
- 실행 시 출력 경로와 작업 디렉터리를 명시하여 결과물이 저장소 루트, 공통 `build/`, 작업 폴더 루트 또는 다른 버전 폴더에 섞이지 않게 한다.
- 버전별 기록에는 실행 명령, 환경과 설정, 관련 코드의 버전 또는 커밋, 결과물의 상대 경로를 남겨 재현할 수 있게 한다.
- 작업 폴더의 `README.md`에는 버전별 목적, 주요 변경 사항, 결과 요약 및 `BUG.md` 또는 `TEST.md` 링크를 유지한다.

## 서비스 코드와의 경계

- 이 디렉터리는 서비스 빌드 및 배포 대상에 포함하지 않는다.
- 실험에서 확인한 수정 사항을 서비스에 반영할 때는 정식 소스 위치에 적용하고 필요한 정식 테스트를 추가한다. 관련 변경 내용과 검증 결과는 해당 버전의 기록에 남긴다.
