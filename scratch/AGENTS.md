# scratch 사용 규칙

## 용도

`scratch/`는 실제 서비스 코드에 포함하지 않을 디버깅용 임시 코드, 성능 테스트, 구현 테스트 및 실험 자료를 두는 공간이다. 작업 중 필요한 자료를 이곳에 저장하되, 작업이 끝나면 아래 판단 기준에 따라 남길 것을 선별한다. 모든 작업에 폴더나 기록을 만들 필요는 없다.

해당 자료들을 보관하는 이유는 사용자가 포트폴리오를 작성할 때 빠르게 회고하기 위함이다.

## 기록과 보존 판단 기준

- 사용자가 명시적으로 요청하기 전에는 경험 카드, 조사 보고서 등 기록용 문서나 이를 위한 폴더를 만들지 않는다. 조사·분석·검증 요청만으로 기록 파일 생성까지 요청한 것으로 해석하지 않는다. 별도 기록 요청이 없으면 조사 결과는 답변으로 전달한다.
- 사용자가 기록 생성이나 보존을 요청했다면 그 범위 안에서 필요한 최소 자료만 남긴다. 생성했거나 실행에 사용했다는 이유만으로 보존하지 않는다.
- 단순 실행 확인이나 반복 검증은 조건과 결과 한 줄이면 충분하다. 관련 기록이 있으면 그곳에 한 줄을 추가하고, 없으면 최종 답변에 남긴다. 이를 위해 새 폴더나 경험 카드를 만들지 않는다.
- 장시간 실행도 동일하다. 예: `동시 접속 512개로 8시간 실행, 관찰한 범위에서 오류 없음.` 또는 `실행 3시간 12분 후 연결 종료 오류 발생(오류 코드 …).` 정상 상태가 반복되는 로그, 전체 실행 로그, 일회성 실행 스크립트는 남기지 않는다. 실행 시간이 길다는 사실만으로 상세 기록의 가치가 생기지는 않는다.
- 사용자가 기록 생성을 요청한 경우에만, 원인 규명, 가설의 수정, 대안 비교 등 회고할 만한 조사와 판단을 경험 카드로 작성한다. 회고 가치가 있거나 오류가 발생했다는 사실만으로 기록 생성이나 원본 로그 보존을 결정하지 않는다.
- 자료를 남기기 전에 “이 자료를 지우면 어떤 원인·판단·결과를 설명할 수 없게 되는가?”를 판단한다. 한 줄 요약이나 카드 본문으로 충분하면 원본은 제거한다. 필요한 경우에도 오류 주변 로그, 결론에 사용한 측정값, 재현에 꼭 필요한 입력처럼 설명에 필요한 부분만 남긴다.
- 아직 조사 중인 오류의 진단에 필요한 자료는 조사하는 동안 유지할 수 있다. 작업 종료 시 보존 필요성을 다시 판단한다. “나중에 쓸 수도 있음”, “증거는 많을수록 좋음”은 보존 사유가 아니다.

## 폴더 구조

- `scratch/` 바로 아래에는 작업별 폴더만 만든다. 단, 공통 지침인 `AGENTS.md`와 경험 카드 템플릿 `TEMPLATE.md`는 예외로 이 위치에 둔다.
- 작업 폴더 이름은 `<이름>_<YYYY-MM-DD>` 형식으로 작성한다. 날짜는 작업 시작일이며, 이름은 작업 주제를 알아볼 수 있게 작성한다. 예: `echo-throughput_2026-09-15`.
- 사용자가 기록 생성을 요청하여 경험 카드를 작성하는 경우에만 작업 폴더의 `README.md`를 [TEMPLATE.md](TEMPLATE.md)로 작성한다. 작업의 목적과 배경, 조사 과정과 판단, 결과 및 근거를 기록한다.
- 이전 자료와 새 자료 모두 보존할 가치가 있고, 스크립트가 수정되어 이전 로그의 분석과 호환이 불가능한 경우에만 작업 폴더 내부에 `001/`, `002/`, `003/`처럼 숫자로만 된 버전 폴더를 순서대로 만든다. 아래 구조는 예시이며, 사용하지 않는 폴더는 만들지 않는다.

```text
scratch/
├── AGENTS.md
├── TEMPLATE.md
└── echo-throughput_2026-09-15/
    ├── README.md
    ├── 001/
    │   ├── run.ps1
    │   ├── inputs/
    │   ├── logs/
    │   └── results/
    └── 002/
        ├── run.ps1
        ├── inputs/
        ├── logs/
        └── results/
```

## 템플릿 사용

- 경험 카드가 필요한 작업은 [TEMPLATE.md](TEMPLATE.md) 하나만 사용한다. 한 작업의 조사와 검증은 작업 폴더의 `README.md` 경험 카드 하나에 함께 기록한다. 한 줄로 충분한 작업에는 템플릿을 적용하지 않는다.
- 조사 과정에서 판단이 바뀐 흐름을 남기고, 필요하면 `가설 → 시도 → 결과 → 다음 판단`을 반복하여 작성한다.
- 경험 카드는 해당 작업에 의미 있는 항목만 작성하고, 해당하지 않는 항목은 생략한다. 결론에 영향을 주지만 확인하지 못한 내용은 `미확인` 또는 `추가 확인 필요`로 표시한다. 가설과 확인된 사실을 구분하며, 수행하지 않은 테스트나 확인하지 않은 결과를 완료한 것으로 기록하지 않는다.
- 가장 중요한 것은 문장의 가독성이다. 

## 스크립트 및 자료 버전 관리

- 버전별로 보존하기로 선별한 임시 코드와 스크립트, 측정값, 분석 자료만 해당 버전 폴더 안에 남긴다. 필요하면 하위 폴더를 만든다.
- 작업 폴더의 `README.md` 경험 카드에는 버전별 목적, 주요 변경 사항과 결과를 조사 흐름에 연결하여 기록한다.
- 경험 카드의 `증거` 항목에는 버전과 어떤 내용이 관찰되었는지 짧게 적는다.

## 작업 완료 후 정리 및 커밋 범위

- 작업을 마칠 때 별도 요청을 기다리지 않고 이번 작업에서 생성한 자료를 정리한다. 위 보관 규칙이 모든 중간 자료를 영구 보관하거나 커밋하라는 뜻은 아니다.
- 커밋에는 위 판단 기준으로 선별한 기록과 자료만 남긴다. 경험 카드, 환경·설정, 측정값, 로그를 일괄 필수 목록으로 취급하지 않는다. 한 줄 결과로 충분하면 별도 증거 파일은 남기지 않는다. 중복 보고서와 로그, 동일 내용을 담은 여러 형식의 결과 파일은 통합한다.
- 커밋으로 복원할 수 있는 소스 복사본과 소스 압축 파일, 빌드 중간 산출물, 캐시, 불필요한 임시 코드와 폐기된 측정 로그는 제거한다. 조사 중 확인한 원인과 판단에 영향을 준 측정 제외 사유는 경험 카드를 작성하는 경우 그 안에 요약한다. 삭제한 파일마다 별도 기록을 남기지는 않는다.
- 빌드로 복구할 수 없는 실행 파일과 DLL도 구체적인 재현 목적이 있을 때만 `artifacts/`에 로컬로 보관하고 Git에서 제외한다. Git 제외, 압축, 다른 폴더로 이동하는 것은 불필요한 자료를 제거하는 대신 사용할 수 없다.
