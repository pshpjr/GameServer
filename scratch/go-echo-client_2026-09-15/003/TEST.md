# 테스트 기록: 세션 확장 및 스케줄링 계측

- 작업일: 2026-09-15

## 1. 테스트 목적

클라이언트의 세션 상한을 측정에 근거해 정한다.

## 2. 테스트 대상

- 대상 코드: main.go, main_test.go.
- 변경: 상한 4096 검토, runtime/metrics의 실행 가능 상태 대기시간 계측.
- 관련 버그: 초기 연결 거부 관찰.

## 3. 테스트 환경

Ryzen 7 9800X3D, 16논리 CPU, Windows, Go 1.27.1, NetLibTest_Echo, batch=32, delay=0.

## 4. 전제 조건

현재 서버의 MAX_SESSIONS는 소스 기준 15000, listen backlog는 128이다. 동일 PC의 loopback 부하 검사다.

## 5. 테스트 방법

64·256·1024세션을 각 5초 순차 실행하고 500ms 간격으로 클라이언트 CPU·메모리를 표본 수집했다. 명령은 results/scale.json 참조.

## 6. 예상 결과

세션 증가 시 오류 및 클라이언트 스케줄링 대기 증가 여부를 확인한다.

## 7. 실제 결과

[측정값](results/scale.json). 64·256세션은 통과했다. 1024개 동시 연결 시 545개 연결 성공, 479개 connection refused가 관찰되어 더 큰 검사로 진행하지 않았다.

## 9. 분석

오류는 송수신 중이 아닌 연결 시도 단계였다. 서버가 접속 요청을 처리하기 전에 연결 요청이 몰리는 영향이 의심됐다. backlog가 근본 원인임을 서버 내부 계측으로 확정하지 않았다.
