# 버그 조사 및 해결 기록: 0시간 통계 경계값

## 1. 문제 요약

001의 종료 직전 통계에 NaN/Inf 또는 매우 큰 p95가 표시되어 대기시간과 처리량 해석을 방해했다.

## 2. 증상

[001 단일 세션 로그](../001/results/single.log)와 [부하 로그](../001/results/bounded-load.log)에 비정상 수치가 남아 있다.

## 3. 재현 방법

경과 시간 0으로 report를 호출하거나 RTT 0을 히스토그램에 넣는다. 실제 짧은 마지막 출력 구간에서도 관찰됐다.

## 4. 원인 분석

시간 계산의 경계값을 확인했다. 처리량의 분모가 0이었고, RTT를 마이크로초로 올림한 결과가 0일 때 uint64에서 1을 빼면 언더플로가 발생했다.

## 5. 해결 과정

0시간 구간에 임의의 처리율을 부여하는 대신 출력하지 않도록 했다. RTT 0은 가장 작은 히스토그램 구간에 포함한다.

## 6. 수정 내용

report에 elapsed <= 0 검사 추가. latencyBucket에서 최소 1마이크로초 구간을 사용한다. 측정된 RTT 원본 자체를 1마이크로초로 바꾸지는 않는다.

## 7. 검증

TestZeroTimeReporting에서 두 경계값을 검증했다. 기존 프로토콜 회귀 및 실제 서버 검사도 통과했다. 위 테스트 기록과 결과 링크 참조.

## 8. 결과

002 이후 실제 서버 로그에서 NaN/Inf와 잘못된 큰 p95가 사라졌다.

## 9. 재발 방지

0시간 회귀 검증을 main_test.go에 유지한다. 시간 해상도로 인한 0 측정 가능성을 README에 명시한다.

## 10. 배운 점

부하 클라이언트의 표시 오류도 서버 성능을 잘못 해석하게 만들 수 있으므로 측정 코드의 경계값을 검증해야 한다.
