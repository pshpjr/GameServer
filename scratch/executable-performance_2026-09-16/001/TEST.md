# 테스트 기록: Executable 변경 전·후 성능 비교

- 작업일: 2026-09-16
- 버전 폴더: scratch/executable-performance_2026-09-16/001
- 이전 버전과의 차이: AdGuard 완전 종료 후 정상 측정 결과를 최종 기록으로 통합했다. 사용자의 정리 요청에 따라 중복 소스·빌드 중간 파일·폐기된 측정 자료는 제거했다.

## 1. 테스트 목적

Executable 콜백 전환이 echo 처리량과 지연시간을 악화시키는지 동일 조건으로 비교한다. 주 조건은 512세션·batch 32·delay 0이다.

## 2. 테스트 대상

- 변경 전 NetLib: `792bd0a80642ed67025ab2f8a338a040df6b14f7`.
- 변경 후 NetLib: `679c517d969387e003912c450c985f25ec67302b`.
- 에코 서버: 상위 저장소 `95ddb7df4407e9a77b73932aa8c4b095213946e9`의 동일 NetLibTest_Echo 소스.
- 클라이언트: 기존 Go echo client 004, 양쪽에 동일 바이너리 사용.
- 비교 범위: 변경 커밋의 일반 echo send/recv 경로. 콜백 호출 자체만의 비용을 분리한 실험은 아니다.

## 3. 테스트 환경

Windows 11 Pro, Ryzen 7 9800X3D, 8코어/16논리 CPU. x64 Release, MSVC 19.51.36257.0, Ninja, `/O2 /Ob2 /DNDEBUG`, Tracy OFF. 서버 IOCP 워커와 concurrency는 각각 4다.

AdGuard 프로세스가 없는 상태에서 측정했다. TCP loopback `127.0.0.1:26001`, Go GOMAXPROCS=기본값 16, batch=32, delay=0, timeout=3s, reconnect=false. 패킷은 헤더 포함 10바이트다. 서버와 클라이언트가 같은 PC를 사용했다.

커밋·환경·빌드 옵션·바이너리 SHA-256은 [environment.json](inputs/environment.json)에 보관한다.

## 4. 전제 조건

서버와 클라이언트를 한 쌍씩 새로 실행하고 서버 시작 후 1초 대기했다. 각 실행의 측정 구간에서 목표 연결 수 유지, errors=0, 종료 코드=0을 확인했다. 기존 바이너리 해시를 검증했으며 소스나 클라이언트를 수정하지 않았다.

## 5. 테스트 방법

512세션은 각 4회, 순서 전→후 / 후→전 / 전→후 / 후→전. 64세션은 각 3회, 전→후 / 후→전 / 전→후. 1024세션은 타임아웃 해소 확인용으로 각 1회 실행했다.

클라이언트는 매번 22초 실행했다. 최초 5개 보고 구간을 제외하고 6~20번째 약 1초 구간 15개를 집계했다. 각 실행의 평균 rx를 구한 뒤 반복 실행의 중앙값을 비교했다. 평균 묶음 RTT는 rx로 가중한 구간 평균의 실행별 중앙값이다. 단일 패킷의 순수 서버 처리시간이 아니다.

CPU는 약 500ms 간격 프로세스 CPU 시간 차이를 16논리 CPU로 정규화해 5~20초 구간을 평균했다. p95 값은 히스토그램 구간 상한이며, CSV의 p95UpperMsMean은 구간 상한의 평균으로 정확한 실행 전체 p95가 아니다.

로컬에 남긴 바이너리로 재실행하려면 001을 기준으로 서버 작업 디렉터리를 해당 서버 폴더로 지정한다. 백그라운드 실행에는 `Start-Process -WindowStyle Hidden -PassThru`와 로그 리다이렉션을 사용했고 실행 후 해당 프로세스만 종료했다.

```powershell
# 별도 터미널에서 before 서버 실행. after는 server-after로 바꾼다.
Set-Location .\artifacts\server-before
.\NetLibTest_Echo.exe 26001
# 클라이언트는 001 기준. 64/1024 조건은 sessions 값만 바꾼다.
$env:GOMAXPROCS=$null
.\artifacts\client\echo-client.exe -ip 127.0.0.1 -port 26001 -sessions 512 -batch 32 -delay 0 -duration 22s -timeout 3s
```

바이너리는 로컬 보관용이므로 커밋에 포함하지 않는다. 새 환경에서는 기록된 상위 저장소 커밋의 NetLibTest_Echo와 각 NetLib 커밋을 추출하고, `add_subdirectory(NetLib)` / `add_subdirectory(NetLibTest_Echo)`를 포함한 CMake 진입점으로 동일 Release 옵션을 사용해 재빌드한다. 의존성과 컴파일러 버전은 환경 파일을 참조한다.

## 6. 예상 결과

수백만 pkt/s 수준의 정상 부하에서 오류 없이 실행돼야 한다. 변경 후 처리량 감소와 RTT 증가가 반복되는지 살핀다. 사전에 정한 회귀 허용률이나 통계적 유의수준은 없으며 작은 차이를 개선으로 단정하지 않는다.

## 9. 분석

처음에는 이전 버전까지 수만~수십만 pkt/s와 수십 ms 이상의 지연이 발생했다. 사용자가 원인을 AdGuard 필터링으로 확인했다. 완전 종료 후 동일 서버·클라이언트 바이너리로 약 500만 pkt/s와 64세션 RTT 약 0.40ms가 회복됐다. 필터링이 남아 있던 측정은 최종 비교에서 제외했다. AdGuard를 다시 켜는 역방향 실험은 하지 않았다.

이번 결과는 같은 PC의 짧은 loopback echo 부하에 한정된다. 원격 NIC, 다른 패킷 크기, Group/커스텀 콜백, 장시간 재접속 부하는 미검증이다.
